# 网页版已暂停维护（FROZEN）

**冻结日期：2026-11-13**（用户决定）

## 这条标记约束什么

- `src/web/**`、`web/`、`scripts/web-smoke.mjs`、`scripts/web-shots.mjs`、`npm run build:web`、`npm run test:web` 这一整套**网页版（投稿演示 / 静态托管）**，从冻结之日起**不再接收功能改动**。
- 插件侧（`src/` 除 `src/web` 外）的新功能、字段、时间规则等，**不需要**再同步到网页版；两边行为不一致＝已知状态，不是缺陷。
- 仍然允许的改动：**修 bug 不排斥**（若网页版本身崩了），以及为了让构建不挂而做的适配。任何超出这个范围的网页版改动，先问用户。

## 现状（冻结时的样子）

- 最后一版包含「计划时间三型（指定日期 / 每周 / 循环）」，产物仍在 `web/bundle.js` + `web/bundle.css`（不入库，需 `npm run build:web` 生成）。
- 网页版与插件共享 `src/data/**` 纯模块（types / display / planSchedule / statExpr / csvFormat 等）。**共享模块的任何签名变更仍会波及网页版**——改共享层时若 `tsc` 报 `src/web` 的错，允许最小修一下类型，不必补齐功能。

## 恢复维护怎么做

1. 删掉本文件；
2. 跑一遍 `npm run build:web && npm run test:web` 确认基线可跑（冒烟脚本失败是预期内的，先按当天实际状态重建基线，不要盲改）；
3. 按当时插件的行为补齐欠账（自 2026-11-13 起的功能变更）；
4. 把「恢复维护」写进项目记忆与项目入口页的状态行。
